# Internationalisierung & Zeitzonen

Mit starlette-admin können Sie UI-Strings pro Benutzer lokalisieren und angezeigte Datetimes in die lokale Zeitzone des Betrachters konvertieren, unabhängig davon, wie Ihre Datenbank sie speichert.

> **Vollständiges Beispiel:** Eine vollständige, funktionierende Anwendung, die Internationalisierung und Zeitzonen demonstriert, finden Sie unter [examples/10-i18n-timezone](https://github.com/jowilf/starlette-admin/tree/main/examples/10-i18n-timezone) im GitHub-Repository.


## Das `i18n` Extra installieren

Die Übersetzungsunterstützung erfordert [Babel](https://babel.pocoo.org/). Ohne Babel funktioniert das Admin-Panel weiterhin, fällt aber auf Englisch zurück und überspringt die locale-bewusste Formatierung von Datumsangaben und Zahlen.

=== "pip"
    ```bash
    pip install "starlette-admin[i18n]"
    ```

=== "uv"

    ```bash
    uv add "starlette-admin[i18n]"
    ```

## Die Locale festlegen

```python
from sqlalchemy import create_engine
from starlette_admin import I18nConfig
from starlette_admin.contrib.sqla import Admin
from starlette_admin.i18n import SUPPORTED_LOCALES

engine = create_engine("sqlite:///admin.sqlite")

admin = Admin(
    engine,
    title="My Admin",
    i18n_config=I18nConfig(
        default_locale="en",
        language_switcher=SUPPORTED_LOCALES,
    ),
    secret_key="a-long-random-string",
)
```

`i18n_config` hat den Defaultwert `None`, wodurch das Admin-Panel auf Englisch läuft. Wenn Sie ein `I18nConfig` übergeben, installiert das Admin-Panel die `LocaleMiddleware`. Die Middleware ermittelt bei jedem Request eine Locale und stellt sie Templates sowie den Übersetzungsfunktionen (`gettext` und `lazy_gettext`) in Ihrem gesamten Feld- und View-Code zur Verfügung.

Der Parameter `language_switcher` fügt der Navigationsleiste des Admin-Panels ein Dropdown-Menü hinzu, damit Benutzer ihre Locale auswählen können. Lassen Sie ihn auf dem Defaultwert `None`, um den Switcher auszublenden und sich auf `default_locale` und die Erkennung pro Request zu verlassen.

### `I18nConfig` Referenz

| Attribut | Typ | Defaultwert | Beschreibung |
| --- | --- | --- | --- |
| `default_locale` | `str` | `"en"` | Locale, die verwendet wird, wenn weder Cookie noch Header zu einer unterstützten Locale passen. |
| `language_cookie_name` | `str | None` | `"language"` | Cookie, das gelesen wird, um die Locale des Benutzers zu ermitteln. Auf `None` setzen, um es zu deaktivieren. |
| `language_header_name` | `str | None` | `"Accept-Language"` | Header, der gelesen wird, wenn das Cookie fehlt. Auf `None` setzen, um ihn zu deaktivieren. |
| `language_switcher` | `list[str] | None` | `None` | Locales, die im Switcher der Navigationsleiste angeboten werden. `None` blendet den Switcher aus. |

## Wie die Locale ermittelt wird

`LocaleMiddleware` ermittelt die Locale einmal pro Request, in dieser Reihenfolge:

1. **Cookie:** Der Wert von `language_cookie_name`, sofern er zu einer integrierten unterstützten Locale passt.
2. **Header:** Der `Accept-Language`-Header oder der Header, den Sie in `language_header_name` festgelegt haben, vorbehaltlich derselben Gültigkeitsprüfung.
3. **Default:** Die `default_locale`, wenn weder Cookie noch Header passen.

Die integrierten unterstützten Locales (`starlette_admin.i18n.SUPPORTED_LOCALES`) sind Deutsch, Englisch, Französisch, Portugiesisch, Russisch, Türkisch sowie vereinfachtes und traditionelles Chinesisch. Wenn ein Benutzer eine Sprache in der Navigationsleiste auswählt, schreibt der Switcher das Sprach-Cookie, sodass die Auswahl über Requests hinweg erhalten bleibt, ohne serverseitigen Session-Speicher.

## Zeitzonen

```python
from sqlalchemy import create_engine
from starlette_admin import TimezoneConfig
from starlette_admin.contrib.sqla import Admin

engine = create_engine("sqlite:///admin.sqlite")

admin = Admin(
    engine,
    title="My Admin",
    timezone_config=TimezoneConfig(
        default_timezone="UTC",
        database_timezone="UTC",
        timezone_switcher=["UTC", "Europe/Paris", "America/New_York", "Asia/Tokyo"],
    ),
    secret_key="a-long-random-string",
)
```
!!! note
    Anders als `i18n_config` ist `timezone_config` nicht standardmäßig `None`. Wenn Sie es weglassen, konstruiert die `Admin`-Klasse für Sie ein `TimezoneConfig()`, sodass die Zeitzonenkonvertierung ab Werk aktiviert ist. Das Admin-Panel behandelt naive Datetimes als Werte in der `database_timezone`, deren Defaultwert `"UTC"` ist, und zeigt sie jedem Benutzer in `"UTC"`, dem Defaultwert von `default_timezone`, an, sofern der Benutzer keine andere auswählt.

### Wie die Zeitzone ermittelt wird

`TimezoneMiddleware` ermittelt die Zeitzone einmal pro Request:

1. **Cookie:** Der Wert von `timezone_cookie_name`, dessen Defaultwert `"timezone"` ist, sofern er vorhanden ist.
2. **Default:** Die `default_timezone`, andernfalls.

Der Zeitzonen-Switcher in der Navigationsleiste schreibt dieses Cookie, genau wie der Sprach-Switcher. Für Zeitzonen gibt es kein Äquivalent zum `Accept-Language`-Header, da Browser keinen solchen senden, daher stützt sich die Erkennung vollständig auf Cookies. Client-seitiges JavaScript, das `Intl.DateTimeFormat().resolvedOptions().timeZone` liest, setzt typischerweise das Cookie, ebenso wie der Switcher selbst.

### Wie Feldwerte konvertiert werden

`DateTimeField` und `ArrowField` konvertieren Werte zwischen der `database_timezone` und der ermittelten Zeitzone des Betrachters.

* **Lesen (Listenseite, Detailseite, Export):** Das Admin-Panel behandelt einen naiven Wert aus Ihrer Datenbank als Wert in der `database_timezone` und konvertiert ihn in die Zeitzone des Betrachters, bevor er formatiert wird.
* **Schreiben (Erstellen- und Bearbeiten-Formulare):** Das Admin-Panel behandelt einen eingereichten Wert als Wert in der Zeitzone des Betrachters und konvertiert ihn in die `database_timezone`, bevor er Ihr Modell erreicht.

Infolgedessen können zwei Administratoren in verschiedenen Zeitzonen dieselbe Zeile bearbeiten, und jeder sieht die Zeiten in seiner eigenen Ortszeit, während die Datenbank eine einzige, konsistente Zeitzone beibehält.

### `TimezoneConfig` Referenz

| Attribut | Typ | Defaultwert | Beschreibung |
| --- | --- | --- | --- |
| `default_timezone` | `str` | `"UTC"` | Zeitzone, die verwendet wird, wenn kein Cookie gesetzt ist. Akzeptiert jeden IANA-Zeitzonennamen. |
| `timezone_cookie_name` | `str | None` | `"timezone"` | Cookie, das gelesen wird, um die Zeitzone des Betrachters zu ermitteln. Auf `None` setzen, um es zu deaktivieren. |
| `database_timezone` | `str` | `"UTC"` | Zeitzone, in der Ihre gespeicherten Datetimes angenommen werden. |
| `timezone_switcher` | `list[str] | None` | `None` | Zeitzonen, die im Switcher der Navigationsleiste angeboten werden. `None` blendet den Switcher aus. |
| `use_user_locale_timezone` | `bool` | `True` | Bevorzugt eine aus der Locale des Benutzers abgeleitete Zeitzone gegenüber der `default_timezone`. |

Um einzuschränken, was Benutzer auswählen können, übergeben Sie eine kürzere `timezone_switcher`-Liste. Um für jeden Betrachter eine einzige Zeitzone durchzusetzen, setzen Sie `timezone_switcher` auf `None` und legen `default_timezone` direkt fest, z. B. auf ein unternehmensweites `"Europe/Paris"`.

Der Switcher in der Navigationsleiste rendert den Anzeigenamen jeder Zeitzone und ihren UTC-Offset mit den Template-Globals `get_timezone` und `get_timezone_display_name`. Der Leitfaden [Templates](../advanced/templates.md) dokumentiert diese Globals und alle anderen.
