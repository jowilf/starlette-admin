# Развёртывание

Работа панели администрирования за обратным прокси меняет две вещи, которые при локальной разработке можно игнорировать: секретный ключ должен быть одинаковым во всех рабочих процессах, а генерируемые URL должны отражать HTTPS, даже если приложение видит от прокси только обычный HTTP.

!!! note "Руководства по развёртыванию для конкретных фреймворков"
    На этой странице описано только то, что относится к `Admin`. О базовом приложении и ASGI-сервере читайте здесь:

    * **FastAPI:** [Документация по развёртыванию FastAPI](https://fastapi.tiangolo.com/deployment/)
    * **Uvicorn:** [Документация по развёртыванию Uvicorn](https://www.uvicorn.org/deployment/)

```python
import os

from sqlalchemy import create_engine
from starlette.applications import Starlette
from starlette_admin.contrib.sqla import Admin, ModelView

from myapp.models import Post

engine = create_engine(os.environ["DATABASE_URL"])
app = Starlette()

admin = Admin(
    engine,
    title="My Admin",
    base_url="/admin",
    secret_key=os.environ["ADMIN_SECRET_KEY"],
)
admin.add_view(ModelView(Post))
admin.mount_to(app)
```

```shell title="Запуск за обратным прокси"
uvicorn myapp.main:app --forwarded-allow-ips='*' --proxy-headers
```

## Секретный ключ

Если не передать `secret_key`, `Admin` сгенерирует случайный ключ при запуске. Для одного локального процесса это нормально, но каждый рабочий процесс генерирует свой ключ независимо, поэтому CSRF-токен, подписанный одним процессом, не пройдёт проверку в другом. Прежде чем запускать несколько процессов, задайте `secret_key` из переменной окружения. Полное описание проблемы с несколькими рабочими процессами и того, как используется ключ, см. в разделе [Безопасность](../user-guide/security.md).

## Обратный прокси и HTTPS

`Admin` строит все внутренние ссылки (страницы списка, формы редактирования, экспорт, монтирование `/static`, загруженные файлы, отдаваемые через `/_files/...`) вызовом `request.url_for(...)`, который определяет схему из входящего запроса. Когда прокси вроде Nginx, Caddy или Traefik терминирует TLS и пересылает приложению обычный HTTP, Starlette не может понять, что исходный запрос был по HTTPS, если прокси не отправляет `X-Forwarded-Proto`, а ваш ASGI-сервер ему не доверяет. Если оставить это ненастроенным, сгенерированные ссылки получат схему `http://`, и браузеры будут блокировать или перезаписывать их, когда сама страница загружена по HTTPS.

Исправьте это в двух местах:

1. **Прокси** пересылает заголовок:

    ```nginx title="nginx"
    location /admin/ {
        proxy_pass http://127.0.0.1:8000/admin/;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
    ```

2. **Uvicorn** доверяет ему — через `--proxy-headers` плюс `--forwarded-allow-ips` с указанием IP прокси (или `'*'`, если прокси доступен только из вашей внутренней сети):

    ```shell
    uvicorn myapp.main:app --forwarded-allow-ips='*' --proxy-headers
    ```

Gunicorn-воркер `uvicorn.workers.UvicornWorker` читает те же два параметра из `--forwarded-allow-ips`. Полный набор опций для менеджеров процессов см. в [документации по развёртыванию Uvicorn](https://www.uvicorn.org/deployment/).

!!! warning
    `--forwarded-allow-ips='*'` доверяет пересылаемым заголовкам из **любого** источника. Используйте его только тогда, когда приложение недоступно иначе как через ваш прокси — например, когда оно привязано к частной сети или Unix-сокету. Если приложение доступно напрямую, ограничьте этот параметр реальным IP прокси. Иначе клиент сможет подделать `X-Forwarded-Proto` и `X-Forwarded-For` напрямую.

## Статические ресурсы

CSS и JS панели администрирования поставляются внутри пакета `starlette_admin`, и `Admin` раздаёт их сам через монтирование `/static` под `base_url`, а не с отдельного статического хоста. Параметр `static_dir` позволяет переопределить отдельные файлы (см. раздел [Шаблоны](templates.md)), но не переносит раздачу ресурсов за пределы процесса приложения. Встроенной возможности раздавать их с CDN нет. Если она нужна, добавьте на уровне прокси правило кэширования `Cache-Control` для `{base_url}/static/*`.

С загруженными файлами иначе: `LocalStorage` тоже раздаёт их через приложение (`/_files/{storage}/{path}`, поэтому middleware аутентификации продолжает действовать), а `S3Storage` и другие удалённые бэкенды могут отдавать файлы напрямую от провайдера. См. раздел [Файловое хранилище](../user-guide/file-storage.md).
