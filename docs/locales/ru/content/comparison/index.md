# Сравнение starlette-admin, Django Admin и Flask-Admin

Django Admin, Flask-Admin и starlette-admin решают одну и ту же задачу: они генерируют готовый к использованию в продакшене интерфейс администрирования на основе ваших моделей данных, чтобы вам не приходилось писать CRUD-экраны вручную. Они различаются целевыми веб-стеками, поддерживаемыми ORM и тем, сколько функциональности встроено изначально, а сколько остаётся на вашей стороне.

На этой странице сравниваются все три инструмента. Если вы уже знакомы с Django Admin или Flask-Admin и хотите получить прямое соответствие API, обратитесь к соответствующему руководству по миграции:

* [Переход с Django Admin](django-admin.md)
* [Переход с Flask-Admin](flask-admin.md)

## Краткое сравнение

| | Django Admin | Flask-Admin | starlette-admin |
| --- | --- | --- | --- |
| **Веб-фреймворк** | только Django | только Flask | Starlette, FastAPI и любое ASGI-приложение, способное монтировать подприложения |
| **Модель выполнения** | синхронная (WSGI-first) | синхронная (WSGI) | асинхронная (ASGI-first) |
| **Слой данных** | только Django ORM | SQLAlchemy, MongoEngine, peewee, pymongo | SQLAlchemy, SQLModel, MongoEngine, Beanie, Tortoise ORM или [пользовательский бэкенд](../integrations/custom-backend.md) |
| **UI-инструментарий** | шаблоны Django, классическая тема администрирования | Bootstrap 2/3/4 | [Tabler](https://tabler.io) (Bootstrap 5), тёмная тема, [пользовательские темы](../advanced/custom-themes.md) |
| **Входит в состав фреймворка** | да, часть Django | нет, отдельный пакет | нет, отдельный пакет |
| **Аутентификация** | встроенная через `django.contrib.auth` | своя реализация (`is_accessible`) | подключаемые [`AuthProvider` / `OAuthProvider`](../user-guide/auth.md), собственное хранилище пользователей |

## Когда подходит каждый фреймворк

### Django Admin

Django Admin подходит для нативных приложений на Django. Он зрелый и интегрируется с `django.contrib.auth`, поэтому вы получаете пользователей, группы, разрешения на уровне моделей и историю изменений без какой-либо настройки. Он работает только внутри Django.

### Flask-Admin

Flask-Admin принёс автогенерацию во Flask и популяризировал стиль конфигурации `ModelView`. Он синхронный и привязан к Flask, поэтому не работает на асинхронном стеке.

### starlette-admin

starlette-admin ориентирован на асинхронный стек Python. Если ваше приложение использует FastAPI или Starlette, вы монтируете панель администрирования в своё приложение, и она работает в том же цикле событий. Она работает как с SQL-, так и с NoSQL-слоями данных, сохраняет стиль конфигурации `ModelView` из Flask-Admin и покрывает глубину функциональности, которую ожидают пользователи Django Admin: инлайн-формы, групповые действия, разрешения на уровне запроса и интернационализацию.

## Компромиссы

* **Полноценная система пользователей:** Django Admin поставляется с полной системой пользователей. `django.contrib.auth` берёт на себя управление пользователями, группами, разрешениями и паролями. В starlette-admin вы реализуете `authenticate()` поверх собственного хранилища данных — это больше настройки в начале, но больше архитектурной свободы в дальнейшем.
* **Автоматическая история изменений:** Django Admin записывает историю изменений в `LogEntry`. В starlette-admin вы создаёте журнал аудита самостоятельно, подписываясь на события жизненного цикла ([events](../advanced/events.md)). Это занимает несколько строк кода, но не происходит автоматически.
* **Экосистема сторонних пакетов:** у Django Admin большая экосистема сторонних пакетов для тем, виджетов и работы с данными. starlette-admin покрывает многие из этих функций нативно, однако нишевое расширение, от которого вы зависите, может ещё не существовать.
* **Управление файлами:** Flask-Admin поставляется с `FileAdmin` — браузером файловой системы сервера. starlette-admin работает с файлами, привязанными к полям модели, через [локальный диск или S3](../user-guide/file-storage.md), и не имеет универсального браузера файлов сервера.
