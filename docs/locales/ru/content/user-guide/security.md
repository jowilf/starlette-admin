# Безопасность

`starlette-admin` включает меры защиты от рисков, связанных с эксплуатацией панели администрирования. Защита от межсайтовой подделки запросов (CSRF) и ограничения на размер экспортируемых и импортируемых данных активны сразу после создания экземпляра класса `Admin`.

Эти настройки по умолчанию защищают интерфейс от распространённых атак, но не заменяют стандартные меры безопасности при развёртывании. Ответственность за безопасность транспортного уровня (HTTPS/TLS), сетевой контроль доступа, аутентификацию пользователей (см. [Аутентификация](auth.md)), обновление зависимостей и аудит безопасности остаётся на вас. На этой странице описаны автоматические защиты, настройки, которые вы конфигурируете сами, и параметр `secret_key`, который необходимо задать в продакшене.

## Что включено по умолчанию

```python
from sqlalchemy import create_engine
from starlette.applications import Starlette
from starlette_admin.contrib.sqla import Admin

engine = create_engine("sqlite:///admin.sqlite")
app = Starlette()
admin = Admin(engine, title="My Admin")
admin.mount_to(app)
```

Даже без каких-либо параметров безопасности экземпляр администрирования защищает от нескольких распространённых уязвимостей:

* **Защита от CSRF:** активна для каждой формы и каждого jQuery AJAX-вызова, включая действия над строками и диалоги подтверждения.
* **Флеш-сообщения:** передаются в подписанной cookie, поэтому `SessionMiddleware` не требуется.
* **Очистка имён файлов:** применяется к каждой загрузке файла через бэкенд хранилища.
* **Проверка содержимого изображений:** загрузки в `ImageField` проверяются на уровне байтов с помощью Pillow, если он установлен.
* **Ограничения экспорта:** не более 100 000 строк за один запрос — это предотвращает исчерпание ресурсов и отказ в обслуживании.
* **Ограничения импорта:** не более 10 МБ за один запрос — это ограничивает риск исчерпания памяти.

Ещё одна защита доступна, но отключена по умолчанию: экранирование, которое предотвращает внедрение формул в CSV-файлы и таблицы (XLSX, XLS, ODS). См. [Внедрение формул](#formula-injection).

В разделах ниже эти защиты описаны подробнее, а также объясняется, как настроить контролируемые вами пороговые значения.

## Секретный ключ

```python
admin = Admin(engine, title="My Admin", secret_key="a-long-random-string")
```

`secret_key` — это криптографическая основа для подписания двух cookie: CSRF-токена и cookie флеш-сообщений. Обе используют библиотеку [itsdangerous](https://itsdangerous.palletsprojects.com/), поэтому клиенты могут читать эти cookie, но не могут подделать или изменить их содержимое без ключа.

!!! warning "Всегда задавайте явный секретный ключ в продакшене"
    Если вы не укажете `secret_key`, экземпляр `Admin` сгенерирует случайный ключ при запуске и выдаст предупреждение `UserWarning`. Для локальной демонстрации это допустимо, но в развёртывании с несколькими воркерами такой подход ломается. При запуске нескольких воркеров, например `uvicorn --workers 4`, Gunicorn или нескольких контейнеров, каждый процесс генерирует собственный ключ. CSRF-токен, подписанный воркером, который отдал форму, не пройдёт валидацию, если отправку обработает другой воркер, — в результате на случайно меняющейся доле запросов будут возникать ошибки недействительного CSRF-токена. Задайте `secret_key` явно, прежде чем масштабироваться за пределы одного процесса.

## Защита от CSRF

`CSRFMiddleware` использует шаблон подписанного double-submit cookie для предотвращения межсайтовой подделки запросов. Он выдаёт cookie `starlette_admin_csrftoken` на безопасных HTTP-методах (`GET`, `HEAD`, `OPTIONS` и `TRACE`). Для изменяющих запросов middleware проверяет эту cookie по заголовку `X-CSRFToken` либо по скрытому полю формы `csrftoken`.

Каждый встроенный шаблон администрирования (`create`, `edit` и `login`) выводит скрытое поле автоматически:

```jinja
{{ csrf_input(request) }}

```

Входящий в комплект JavaScript также добавляет заголовок к каждому jQuery AJAX-вызову, поэтому действия над строками и другие асинхронные взаимодействия защищены без дополнительного кода. Вызывайте `csrf_input(request)` самостоятельно только тогда, когда создаёте пользовательские формы вне стандартных шаблонов. См. [Пользовательские представления](custom-views.md).

## Загрузка файлов

Каждая загрузка, проходящая через бэкенд [файлового хранилища](file-storage.md), очищается функцией `secure_filename`. Компоненты пути, используемые для обхода каталогов, удаляются, а символы вне диапазона `[A-Za-z0-9_.-]` заменяются подчёркиваниями (`_`). Отключить это нельзя.

Ограничения по типу содержимого и размеру задаются для каждого поля с помощью `accept` и `max_size`:

```python
from starlette_admin.fields import FileField


class DocumentView:
    invoice = FileField(accept=".pdf,.docx", max_size=5 * 1024 * 1024)  # лимит 5 МБ
```

Без этих параметров `FileField` принимает файлы любого типа и размера. Исключение — `ImageField`: по умолчанию он использует `accept="image/*"`, а при установленном Pillow добавляет валидатор, который открывает загруженный файл через `PIL.Image`, чтобы убедиться, что байты декодируются как изображение, вместо того чтобы доверять метаданным, предоставленным браузером.

!!! important "Ограничивайте размер запросов на уровне веб-сервера"
    Не полагайтесь только на `max_size`. Эта проверка на уровне приложения выполняется лишь после того, как сервер получил весь payload запроса. Чтобы предотвратить атаки типа «отказ в обслуживании» (DoS), ограничьте размер тела запроса в конфигурации веб-сервера, например с помощью `client_max_body_size` в NGINX или аналогичной настройки на вашем балансировщике нагрузки.

!!! warning "Расширения файлов и заголовки Content-Type можно подделать"
    Атрибут `accept` опирается на расширение имени файла и заголовок `Content-Type`, предоставленный браузером, причём и то и другое злоумышленник может подделать. Файл, который выглядит как `invoice.pdf`, может содержать исполняемый код.

    Для файлов, не являющихся изображениями, дополните `accept` пользовательским валидатором, который проверяет магические байты файла. Библиотеки [`filetype`](https://github.com/h2non/filetype.py) и [`python-magic`](https://github.com/ahupp/python-magic) позволяют проверить реальный формат файла:

    ```python
    import filetype
    from starlette.datastructures import UploadFile
    from starlette.requests import Request
    from starlette_admin.fields import BaseField

    ALLOWED_DOCUMENT_MIME_TYPES = {
        "application/pdf",
        "application/msword",
        "application/vnd.openxmlformats-officedocument.wordprocessingml.document",
    }

    def validate_document_type(
        request: Request, field: BaseField, upload: UploadFile, form_values: dict
    ) -> None:
        upload.file.seek(0)
        try:
            header = upload.file.read(2048)
            kind = filetype.guess(header)
            detected = kind.mime if kind else "application/octet-stream"
        finally:
            upload.file.seek(0)

        if detected not in ALLOWED_DOCUMENT_MIME_TYPES:
            raise ValueError(
                f"Invalid file type '{detected}'. Only PDF, DOC, and DOCX are allowed."
            )
    ```

    Примените валидатор с помощью `FileField(..., validators=[validate_document_type])`. Полную реализацию см. в [`examples/04-filestorage`](https://github.com/jowilf/starlette-admin/tree/main/examples/04-filestorage).

## Ограничения экспорта

```python
from starlette_admin.export import ExportConfig

admin = Admin(engine, title="My Admin", export_config=ExportConfig(max_rows=50_000))
```

| Атрибут | По умолчанию | Описание |
| --- | --- | --- |
| `max_rows` | `100_000` | Максимальное количество строк в одном запросе на экспорт. При превышении лимита выводится флеш-сообщение об ошибке, и пользователь возвращается к представлению списка. Установите `None`, чтобы снять ограничение. |
| `restrict_url_download` | `True` | Применяется к ссылкам на файлы вида «только URL». Ограничивает экспортный ZIP-архив файлами, источник которых совпадает с `base_url` панели администрирования. |
| `max_download_size` | `20 MB` | Максимальный размер загрузки «только URL», упаковываемой в экспортный ZIP-архив. Более крупные файлы пропускаются с записью предупреждения в журнал. |
| `safe_download_url` | `None` | Пользовательская функция обратного вызова с сигнатурой `(url, request) -> str`. |

О том, как формируется ZIP-архив, см. в разделе [Экспорт и импорт](export-import.md).

### Внедрение формул {#formula-injection}

Табличные редакторы интерпретируют значение ячейки, начинающееся с `=`, `+`, `-` или `@`, как формулу. Если недоверенный пользователь сохранит в экспортируемое поле payload вроде `=HYPERLINK(...)`, табличное приложение выполнит его, когда администратор откроет файл. Это называется CSV-инъекцией, или внедрением формул.

Поскольку экспортируемые значения записываются точно так, как они хранятся в базе данных, экранирование формул **по умолчанию отключено**. Экспортёр CSV и экспортёры Tablib (`xlsx`, `xls` и `ods`) принимают параметр `escape_formulas`. Когда он включён, к любой строке, начинающейся с триггерного символа, добавляется одинарная кавычка (`'`) в начале, что заставляет приложение отображать значение как обычный текст.

!!! warning "Включайте экранирование формул для данных, вводимых пользователями"
    Если любая учётная запись, кроме администраторской, может записывать данные в экспортируемое поле, установите `escape_formulas=True`. Без этого значения, контролируемые злоумышленником, могут выполнить системные команды или похитить данные, когда кто-то откроет файл локально.

Чтобы включить экранирование, замените строку формата на явный экземпляр экспортёра:

```python
from starlette_admin.contrib.sqla import ModelView
from starlette_admin.export import CsvExporter, TablibExporter


class ProductView(ModelView):
    exporters = [
        CsvExporter(escape_formulas=True),
        TablibExporter("xlsx", escape_formulas=True),
        "json",
    ]
```

## Ограничения импорта

```python
from starlette_admin.importers import ImportConfig

admin = Admin(
    engine,
    title="My Admin",
    import_config=ImportConfig(
        max_upload_size=5 * 1024 * 1024,
        max_rows=50_000,
    ),
)
```

| Атрибут | По умолчанию | Описание |
| --- | --- | --- |
| `max_upload_size` | `10 MB` | Проверяется сразу после получения запроса, до начала какого-либо разбора. |
| `max_rows` | `100_000` | Максимальное количество строк в одном запросе на импорт. Панель подсчитывает строки в предварительном проходе и отклоняет файл большего размера ответом HTTP 400 до создания какой-либо записи в базе данных. Установите `None`, чтобы снять ограничение. |

Импорт полностью отклоняет ZIP-архивы, что исключает риск атак с использованием ZIP-бомб на этот эндпоинт. Поля `FileField` и `ImageField` также исключены из массового импорта, поскольку по умолчанию имеют `exclude_from_import=True`, поэтому пользователи прикрепляют файлы по одному через формы создания или редактирования.

## Чего эта страница не охватывает

Встроенные защиты устраняют риски внутри самой кодовой базы панели администрирования. Они не обеспечивают безопасность вашей архитектуры в целом. Следующие операционные меры выходят за рамки `starlette-admin` и остаются вашей ответственностью:

* **Безопасность транспорта:** обслуживайте панель по HTTPS. Cookie для CSRF и флеш-сообщений подписаны, но не зашифрованы, поэтому любой, кто перехватит трафик по обычному HTTP, сможет прочитать их содержимое.
* **Аутентификация и авторизация:** экземпляр `Admin` открыт для всех, пока вы не подключите `AuthProvider`. Без него все эндпоинты и маршруты доступны без ограничений. См. [Аутентификация](auth.md).
* **Сетевая доступность:** если панели администрирования не нужен публичный доступ, разместите её за файрволом, VPN или списком разрешённых IP-адресов.
* **Актуальность зависимостей:** следите за рекомендациями по безопасности и своевременно обновляйте `starlette-admin`, Starlette, драйвер вашей ORM и остальные зависимости.
* **Действия после аутентификации:** защита от CSRF и валидация загрузок не ограничивают то, что может делать вошедший пользователь. Детальный контроль доступа полностью определяется проверками прав, которые вы пишете в `is_accessible`, `can_create`, `can_edit` и `can_delete`. См. [Аутентификация](auth.md).

Рассматривайте эту страницу как руководство по настройке пакета администрирования, а не как чек-лист по защите всего вашего продакшен-развёртывания.
