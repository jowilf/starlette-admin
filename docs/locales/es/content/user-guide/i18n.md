# Internacionalización y zonas horarias

Con starlette-admin, puede localizar las cadenas de la interfaz por usuario y convertir los datetimes mostrados a la zona horaria del usuario que los visualiza, de forma independiente de cómo su base de datos los almacene.

> **Ejemplo completo:** Para ver una aplicación completa y funcional que demuestra la internacionalización y las zonas horarias, consulte [examples/10-i18n-timezone](https://github.com/jowilf/starlette-admin/tree/main/examples/10-i18n-timezone) en el repositorio de GitHub.


## Instalar el extra `i18n`

El soporte de traducción requiere [Babel](https://babel.pocoo.org/). Sin él, el panel de administración sigue funcionando, pero recurre al inglés y omite el formato de fechas y números según la configuración regional.

=== "pip"
    ```bash
    pip install "starlette-admin[i18n]"
    ```

=== "uv"

    ```bash
    uv add "starlette-admin[i18n]"
    ```

## Establecer la configuración regional

```python
from sqlalchemy import create_engine
from starlette_admin import I18nConfig
from starlette_admin.contrib.sqla import Admin
from starlette_admin.i18n import SUPPORTED_LOCALES

engine = create_engine("sqlite:///admin.sqlite")

admin = Admin(
    engine,
    title="My Admin",
    i18n_config=I18nConfig(
        default_locale="en",
        language_switcher=SUPPORTED_LOCALES,
    ),
    secret_key="a-long-random-string",
)
```

`i18n_config` tiene como valor predeterminado `None`, lo que ejecuta el panel de administración en inglés. Cuando pasa un `I18nConfig`, el panel instala `LocaleMiddleware`. El middleware resuelve una configuración regional en cada solicitud y la expone a las plantillas y a las funciones de traducción (`gettext` y `lazy_gettext`) en todo su código de campos y vistas.

El parámetro `language_switcher` añade un menú desplegable a la barra de navegación del panel para que los usuarios puedan seleccionar su configuración regional. Déjelo como `None`, el valor predeterminado, para ocultar el selector y confiar en `default_locale` y en la detección por solicitud.

### Referencia de `I18nConfig`

| Atributo | Tipo | Valor predeterminado | Descripción |
| --- | --- | --- | --- |
| `default_locale` | `str` | `"en"` | Configuración regional utilizada cuando ninguna cookie ni encabezado coincide con una configuración regional admitida. |
| `language_cookie_name` | `str | None` | `"language"` | Cookie que se lee para detectar la configuración regional del usuario. Establezca `None` para desactivarla. |
| `language_header_name` | `str | None` | `"Accept-Language"` | Encabezado que se lee cuando la cookie no está presente. Establezca `None` para desactivarlo. |
| `language_switcher` | `list[str] | None` | `None` | Configuraciones regionales ofrecidas en el selector de la barra de navegación. `None` oculta el selector. |

## Cómo se detecta la configuración regional

`LocaleMiddleware` resuelve la configuración regional una vez por solicitud, en este orden:

1. **Cookie:** El valor de `language_cookie_name`, si coincide con una configuración regional integrada admitida.
2. **Encabezado:** El encabezado `Accept-Language`, o el encabezado que establezca en `language_header_name`, sujeto a la misma comprobación de validez.
3. **Predeterminado:** La `default_locale`, cuando ni la cookie ni el encabezado coinciden.

Las configuraciones regionales integradas admitidas (`starlette_admin.i18n.SUPPORTED_LOCALES`) son alemán, inglés, francés, portugués, ruso, turco y chino tanto simplificado como tradicional. Cuando un usuario selecciona un idioma en la barra de navegación, el selector escribe la cookie de idioma, de modo que la elección persiste entre solicitudes sin necesidad de almacenamiento de sesión en el servidor.

## Zonas horarias

```python
from sqlalchemy import create_engine
from starlette_admin import TimezoneConfig
from starlette_admin.contrib.sqla import Admin

engine = create_engine("sqlite:///admin.sqlite")

admin = Admin(
    engine,
    title="My Admin",
    timezone_config=TimezoneConfig(
        default_timezone="UTC",
        database_timezone="UTC",
        timezone_switcher=["UTC", "Europe/Paris", "America/New_York", "Asia/Tokyo"],
    ),
    secret_key="a-long-random-string",
)
```
!!! note
    A diferencia de `i18n_config`, `timezone_config` no es `None` de forma predeterminada. Si lo omite, la clase `Admin` construye un `TimezoneConfig()` por usted, de modo que la conversión de zonas horarias está activada desde el principio. El panel trata los datetimes ingenuos (naive) como si estuvieran en la `database_timezone`, cuyo valor predeterminado es `"UTC"`, y los muestra a todos los usuarios en `"UTC"`, la `default_timezone` predeterminada, salvo que el usuario seleccione otra.

### Cómo se detecta la zona horaria

`TimezoneMiddleware` resuelve la zona horaria una vez por solicitud:

1. **Cookie:** El valor de `timezone_cookie_name`, que es `"timezone"` de forma predeterminada, si está presente.
2. **Predeterminado:** La `default_timezone`, en caso contrario.

El selector de zonas horarias de la barra de navegación escribe esta cookie, exactamente igual que el selector de idioma. Las zonas horarias no tienen un equivalente del encabezado `Accept-Language` porque los navegadores no envían uno, por lo que la detección depende por completo de las cookies. Un JavaScript del lado del cliente que lea `Intl.DateTimeFormat().resolvedOptions().timeZone` suele establecer la cookie, al igual que el propio selector.

### Cómo se convierten los valores de los campos

`DateTimeField` y `ArrowField` convierten los valores entre la `database_timezone` y la zona horaria resuelta del usuario que visualiza.

* **Lectura (página de lista, página de detalle, exportación):** El panel trata un valor ingenuo procedente de su base de datos como un valor en la `database_timezone` y lo convierte a la zona horaria del usuario antes de formatearlo.
* **Escritura (formularios de creación y edición):** El panel trata un valor enviado como un valor en la zona horaria del usuario y lo convierte a la `database_timezone` antes de que llegue a su modelo.

Como resultado, dos administradores en zonas horarias distintas pueden editar la misma fila y cada uno ve las horas en su hora local, mientras que la base de datos mantiene una única zona horaria coherente.

### Referencia de `TimezoneConfig`

| Atributo | Tipo | Valor predeterminado | Descripción |
| --- | --- | --- | --- |
| `default_timezone` | `str` | `"UTC"` | Zona horaria utilizada cuando no hay ninguna cookie establecida. Acepta cualquier nombre de zona horaria IANA. |
| `timezone_cookie_name` | `str | None` | `"timezone"` | Cookie que se lee para detectar la zona horaria del usuario. Establezca `None` para desactivarla. |
| `database_timezone` | `str` | `"UTC"` | Zona horaria en la que se asume que están sus datetimes almacenados. |
| `timezone_switcher` | `list[str] | None` | `None` | Zonas horarias ofrecidas en el selector de la barra de navegación. `None` oculta el selector. |
| `use_user_locale_timezone` | `bool` | `True` | Prefiere una zona horaria inferida de la configuración regional del usuario sobre la `default_timezone`. |

Para restringir lo que los usuarios pueden seleccionar, pase una lista `timezone_switcher` más corta. Para imponer una única zona horaria a todos los usuarios, establezca `timezone_switcher` en `None` y defina directamente la `default_timezone`, por ejemplo, con un valor global de empresa como `"Europe/Paris"`.

El selector de la barra de navegación muestra el nombre visible y el desfase UTC de cada zona horaria mediante las variables globales de plantilla `get_timezone` y `get_timezone_display_name`. La guía de [Plantillas](../advanced/templates.md) documenta estas variables globales y todas las demás.
